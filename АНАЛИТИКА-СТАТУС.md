# Эхо — протокол реализации аналитики FE

Основание: `docs/04-development/analytics-tz.md` (28.10.2026, PM Роман).
Реализация подготовлена на базе локального комплекта «Эхо v10.28 + API», **не** на базе актуальной ветки GitHub EchoWeb: доступ к содержимому репозитория и серверу BE не подтверждён.

## P0: события к релизу

| № | Событие | Статус | Комментарий |
|---|---|---|---|
| 1 | `session_started` | Реализовано в FE | UUID, cookie на 12 месяцев, новая сессия после 30 минут неактивности, UTM, источник и тип устройства. Не дублируется при обновлении страницы внутри активной сессии. |
| 2 | `page_viewed` | Реализовано для поддерживаемых страниц | Главная, каталог, поиск, обычный профиль, профиль автора. Типов для страниц входа, редактирования и Studio в ТЗ нет — не выдуманы. |
| 3 | `film_card_impression` | Реализовано на существующих списках | Главная `home_popular`, каталог, поиск. ≥50% / ≥1 с; `home_now_discussed` и `home_latest` как списки фильмов в текущем UI отсутствуют. |
| 4 | `film_card_clicked` | Реализовано | Корректные `film_id`, `list_type`, `position` для тех же списков; защита от повторного клика в пределах 2 с. |
| 5 | `film_page_viewed` | Реализовано | При переходе на страницу фильма, с `source` (список, профиль, рецензия или direct). |
| 6 | `review_expanded` | Реализовано | Раскрытие полного текста и спойлера, без событий на сворачивание. |
| 7 | `review_form_opened` | Требуется доработка UI / согласование | По ТЗ событие происходит **при переключении** формы оценки в режим рецензии. В v10.28 форма рецензии отображается сразу, переключателя нет. Хук для `[data-review-mode="review"]` готов; не подменяем событие простым просмотром формы. |
| 8 | `review_started` | Реализовано | Первый символ в заголовке/тексте, один раз на UUID `form_instance_id`; ID передаётся в `POST /v2/reviews`. |
| 9 | `partner_placement_impression` | Ожидает размещение и ID от PM/BE | Observer для `[data-analytics-integration-id]` готов. Партнёрского блока и списка `integration_id` в текущем UI нет. |

## Общая архитектура

- `src/analytics.js`: `track()`, строгий белый список событий/props, общие поля, очередь, отправка по `POST /api/events` каждые 7 с или при 20 событиях, одна повторная попытка, `sendBeacon` на `pagehide`.
- `anon_id` в cookie (`SameSite=Lax`, `Secure` по HTTPS) и fallback в localStorage, `session_id` в localStorage; `page_view_id` обновляется при реальном переходе, а не при повторной отрисовке SPA.
- Показы через `IntersectionObserver`, с отменой таймера при уходе объекта из видимой области.
- Только утверждённые props; пароли, токены, тексты рецензий, комментариев и поисковые запросы **не включаются**.
- `is_test=true` на dev/staging и для ID тестовых аккаунтов из `.env`. В production консольный вывод событий отключён.
- `src/api.js`: `anon_id` и `session_id` добавлены к телу запросов регистрации и входа, `form_instance_id` — к отправке рецензии.
- **События, закреплённые за Backend, на FE не дублируются.** Отдельный транспорт аналитики необходим для пакетной отправки и `sendBeacon`; обычные запросы приложения по-прежнему идут через `request()`.
- Если `VITE_API_URL` пуст, сайт и аналитика работают в демо-режиме; **в сеть события не отправляются**.

## Проверка по пункту 6 ТЗ

| Проверка | Статус |
|---|---|
| 1. Одна запись в БД без дублей | FE UUID + дедупликация в браузере готовы; дедупликация в БД ждёт BE. |
| 2. Общие поля | Пройдено unit-тестами (10 полей). |
| 3. Связка анонимного визита и регистрации | `anon_id` передаётся, связывание на BE не проверено. |
| 4. Полная воронка | Частично: FE-события готовы, события записи в БД и переключатель формы ждут BE/UI. |
| 5. Показ менее 1 с | Проверен тестом с отменой таймера. |
| 6. `list_type` | Проверены существующие списки `home_popular`, `catalog`, `search`; остальные отсутствуют в UI. |
| 7. Закрытие вкладки | Проверен вызов `sendBeacon`; доставка в реальную БД не проверена. |
| 8. Нет персональных данных | Проверен whitelist props. |
| 9. Отказ `/api/events` | Проверены одна повторная попытка и независимость от UI; реальный staging не проверен. |

**Итог:** 15 автоматизированных unit/API-тестов пройдены, сборка `npm run build` выполнена, демо-сайт проверен в Chromium (десктоп и 390 px, переходы, ввод рецензии, отсутствие ошибок JavaScript). Сквозная приёмка на staging и PR **не выполнены**: нет доступа к BE, не согласован контракт `/api/events` (массив, 204, лимит пачки, CORS, дедупликация), не готовы таблица `events`, `/go/{integration_id}` и список размещений.
