# «Эхо» — подключение Яндекс Метрики

## Что сделано

- В проект добавлен `src/metrika.js`: загрузка стандартного счётчика Яндекс Метрики, только если указан корректный номер счётчика и пользователь дал согласие.
- Для SPA настроена ручная отправка `ym(counterId, 'hit', virtualUrl, {title, referer})` при смене экранов. `defer: true` исключает автоматический дополнительный просмотр.
- Отслеживаются: главная, каталог, поиск, страницы фильмов, профили, экран авторизации и студия. Повторный `render()` без смены страницы не создаёт дубль.
- В виртуальные URL не попадают текст поиска, никнеймы, email, тексты рецензий, токены и другие пользовательские поля. Передаётся только тип страницы и публичный числовой ID фильма.
- Метрика не запускается на `localhost` и `file://`, чтобы не загрязнять статистику разработкой и автономным демо.
- Добавлено ненавязчивое уведомление с выбором «Разрешить / Отказаться» (показывается только при настроенном счётчике на опубликованном сайте). До согласия внешний скрипт не загружается.
- Вебвизор включён по присланным настройкам счётчика **только после согласия посетителя**. Поля ввода и пользовательский контент помечаются классами `ym-disable-keys` / `ym-hide-content`, чтобы ограничить запись приватных данных. Перед публичным запуском нужна проверка настроек Вебвизора и политики конфиденциальности.
- Первая-party аналитика `/api/events` продолжает работать отдельно, как и прежде.

## Как включить

1. Счётчик **114072239** уже прописан в `.env` проекта (предоставлен владельцем сайта).
2. Откройте `.env` и впишите:

   ```env
   VITE_YANDEX_METRIKA_ID=114072239
   ```

   Изменять значение не требуется, если это счётчик вашего опубликованного сайта.
3. Выполните `npm run build` и опубликуйте содержимое папки `dist/` на HTTPS-домене сайта. При запуске `npm run dev` счётчик намеренно не отправляет статистику с `localhost`.
4. Откройте опубликованный сайт, нажмите «Разрешить» в уведомлении, перейдите из каталога в фильм и проверьте счётчик в интерфейсе Метрики. Блокировщики рекламы могут препятствовать отправке.

**Важное:** в автономном `preview.html` Метрика отключена; он предназначен для проверки интерфейса без сервера. Установка номера счётчика не делает сайт опубликованным автоматически.

## Что требует согласования

ТЗ от 28.10.2026 предполагает **собственный сервер и отсутствие сторонних сервисов аналитики**. Яндекс Метрика является сторонним сервисом, поэтому перед выпуском нужно согласовать её использование с PM и проверить требования к уведомлению о cookies, политике конфиденциальности и обработке данных. Также нужно согласовать цели конверсии: готов метод `metrika.goal(...)` для действий браузера, но он не вызывается автоматически и не подменяет события Backend.

## Проверка

`npm test` — unit-тесты исходной аналитики и интеграции Метрики; `npm run build` — сборка статического сайта.

**Статус:** номер счётчика **114072239** установлен, сборка готова к размещению на HTTPS-домене. Домен и доступ к публикации не предоставлены. Фактическая доставка данных в Метрику и PR в GitHub не проверены.


## Настройки из присланного кода

- `ssr: true`, `webvisor: true`, `clickmap: true`, `ecommerce: "dataLayer"`, `accurateTrackBounce: true`, `trackLinks: true`.
- `defer: true` добавлено для SPA: просмотры отправляются вручную при изменении экрана, чтобы не удваивать счётчик.
- Начальный `url` и последующие `hit` используют безопасный виртуальный адрес, а `referrer` очищен до домена: поисковые запросы и токены в адресах не уходят в Метрику.
- `noscript`-пиксель не вставлен: он отправлял бы запрос до получения согласия и в автономном HTML. При отключённом JavaScript Метрика не собирает данные.
- На `file://` и `localhost` счётчик не запускается; нужен опубликованный HTTPS-домен. При наличии блокировщика рекламы отправка может не пройти.
- В `.env` по умолчанию выставлено `VITE_ANALYTICS_ENV=production` для реального выпуска. Для тестового сервера поменяйте на `staging`.
