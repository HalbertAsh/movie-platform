# Эхо v10.28 — основной сайт с подключаемым API

Это **оригинальный интерфейс «Эхо»**, а не новый React-дизайн. Исходные стили `src/styles.css` сохранены. API-клиент и обработчики действий подключены к `src/app.js`.

## Быстрый запуск

1. Установите Node.js 18 или новее (внешние npm-пакеты не требуются).
2. Откройте эту папку в VS Code.
3. Для демонстрации оставьте `.env` таким:

   ```env
   VITE_API_URL=
   ```

4. В терминале из папки проекта выполните:

   ```bash
   npm run dev
   ```

5. Откройте `http://localhost:5173/`.

Для запуска проекта на компьютере используйте `npm run dev`. Отдельный `preview.html` в этот архив не входит.

## Включение API

В файле `.env` задайте реальный адрес тестового бэкенда, например:

```env
VITE_API_URL=https://your-test-api.example
```

Пример адреса выше — заглушка, не рабочий сервер. Перезапустите `npm run dev`. Приложение будет отправлять запросы на `VITE_API_URL` по маршрутам из ТЗ. Если API недоступен, интерфейс не становится белым: показывает уведомление об ошибке и демо-каталог.

**Важно:** реальный URL бэкенда в задаче не предоставлен, поэтому интеграция с настоящим сервером **не проверена**. Сервер должен разрешать CORS для адреса фронтенда и возвращать JSON в ожидаемом формате. Нельзя помещать секреты в `VITE_API_URL` — адрес виден в браузере.

В отличие от Vite-сборки, здесь используется существующий лёгкий Node-сервер, который читает переменную `VITE_API_URL` из `.env` и подставляет её в публичную конфигурацию страницы. Это позволяет сохранить прежнюю структуру сайта **без установки зависимостей**. Все обычные запросы приложения проходят через `request()` в `src/api.js`; пакетная аналитика использует отдельный транспорт, поскольку ей необходим `sendBeacon`.

## Сборка для публикации

```bash
npm run build
```

Появится папка `dist/` с готовым статическим сайтом. Значение `VITE_API_URL` включается в `dist/index.html` во время сборки. Чтобы изменить URL в опубликованной версии, измените `.env` и повторите сборку. Файл `.env` **не копируется** в `dist` и закрыт от выдачи локальным сервером.

## Что подключено

- `POST /v1/auth/login`, `POST /v1/auth/register`, `GET /v1/me`, `GET /v1/me/profile`, `POST /v1/auth/logout`;
- Bearer-токены в localStorage, однократный refresh после 401, переход на экран входа при истечении сессии;
- `/v1/media` и `/v2/media/movie/{tmdbId}/details` для фильмов;
- `GET /v2/reviews` для рецензий и пагинации на странице фильма;
- `PUT /v2/me/ratings/movie/{tmdbId}` для оценки;
- `PUT /v2/me/ratings/movie/{tmdbId}` → `POST /v2/reviews` для рецензии (с отображением статуса модерации);
- `PUT/DELETE /v2/reviews/{id}/like` для лайков с оптимистичным изменением и откатом;
- `PUT/DELETE /v1/me/preferences/movie/{tmdbId}` для топ-5 фильмов;
- загрузка собственного профиля, попытка загрузки чужого профиля по ID, попытка получения своих рецензий на модерации.

## Что ждёт бэкенд / согласование

- **Изменение профиля** (ник, био, аватар): маршрут BE не указан. Кнопка в API-режиме сообщает об отсутствии эндпоинта, не симулирует сохранение.
- **Вход автора, лайк автора, авторский комментарий**: маршруты BE не указаны. В API-режиме интерфейс сообщает «ждёт BE», в демо-режиме работает прототип.
- **Предпочтения режиссёров и актёров**: требуется согласовать их TMDB ID и формат ответа. В API-режиме не отправляются фиктивные идентификаторы.
- **Список оценок пользователя**: в ТЗ нет GET-эндпоинта. В API-режиме демонстрационные оценки не выдаются за реальные.
- **Профиль автора и аналитика Studio**: демо, пока не будет согласован контракт BE.
- **Рецензии в статусе pending**: запрос `GET /v2/reviews?mine=true&status=pending` предполагается, но требует подтверждения BE.
- **Формат тела оценок, регистрации, рецензий и профилей** требует сверки со Swagger.

## Новое: продуктовая аналитика по ТЗ от 28.10.2026

Добавлен модуль `src/analytics.js` без изменения визуального оформления. Он собирает события браузера и **не** дублирует события успешных записей, которые по ТЗ обязан фиксировать Backend. Отдельный транспорт аналитики отправляет пачки через `POST /api/events` (в отличие от обычного API-клиента `request()`) и использует `sendBeacon` при закрытии страницы.

Переменные `.env`:

```env
VITE_API_URL=
VITE_ANALYTICS_ENV=development
VITE_ANALYTICS_TEST_USER_IDS=
```

- Пустой `VITE_API_URL`: демо-сайт; **никакие события не отправляются на сервер**.
- На тестовом сервере укажите адрес API, а `VITE_ANALYTICS_ENV=staging`; события получат `is_test=true` и будут видны в консоли.
- Для публикации используйте `VITE_ANALYTICS_ENV=production`; в production события в консоль не выводятся. Тестовые ID можно перечислить через запятую в `VITE_ANALYTICS_TEST_USER_IDS`.
- Для `POST /api/events` Backend должен принять массив событий, вернуть 204, выполнять дедупликацию по `event_id`, разрешать CORS с домена сайта и поддерживать `sendBeacon` с `Content-Type: application/json` без обязательной авторизации.

```bash
npm test             # 15 новых автоматизированных тестов аналитики и корреляции API
npm run build        # статическая сборка в dist/
node tools/preview.mjs # автономный демо-предпросмотр preview.html
npm run dev          # локальный сайт на http://localhost:5173
```
